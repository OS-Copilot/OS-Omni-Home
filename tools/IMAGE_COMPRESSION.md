# 回放图片的适度压缩

2026-11-12：用户允许适度压缩后，新增独立的图片压缩发布副本。
原网站、原始截图、实验日志、无损包都保留，不覆盖现有素材。

## 实测体积

| 版本 | 完整内容体积 |
| --- | ---: |
| 原始静态资源 | 8.47 GiB |
| 去重及无损压缩包 | 4.24 GiB |
| 本轮适度图片压缩包 | 3.38 GiB |

本轮在无损包基础上再减少约 880 MiB；相对原始内容累计减少约 60.1%。
4,681 个截图路径中，3,407 个改用 WebP，其余保留原格式。
60 条案例及全部步骤保留，截图尺寸不变。

验证结果：通过。核对了 15,323 份独立资源、3,407 个改变的截图路径，
以及 290 个 HTTP 资源（App 入口和回放首尾图片/预览）。
App 文件与既有回放预览的内容散列全部保持一致。
另修复了 Windows MIME 注册表可能缺少 WebP 映射的问题，明确返回 `image/webp`。

## 压缩范围

- 只处理回放点击 `Open screenshot` 打开的完整尺寸截图。
- 采用 WebP quality 94；必要时尝试 98。没有缩小尺寸、删帧或删案例。
- 每张图片解码后与原图核对 RGB PSNR，要求至少 36 dB；不达标或文件不变小的保留原文件。
- 正常回放使用的现有预览图逐字节保留，因此本轮没有进一步降低播放画质。
- App 文件、彩色图标、代码、任务指令、评分、步骤和已有预览图不变。
- 发布副本的回放说明改为明确告知完整尺寸截图可能经过压缩；源结果归档链接保留。

PSNR 是辅助的数值检查，不等于人眼验收，也不代表像素完全一致。
WebP 有损截图可能在极细文字、颜色边缘处存在差异。原图仍在本地和源归档中。

## 构建与检查

先准备已验证的 `dist/compact-site/` 无损包，然后执行：

```powershell
python tools/build_webp_package.py --workers 6
python tools/verify_webp_package.py
python dist/compact-webp-v2/serve.py --port 8914
```

构建器拒绝覆盖已有的非空输出目录。再次构建可通过 `--output` 指定新的 `dist/` 子目录。
未更改的资源复用无损包的只读内容，不通过复制多份大文件浪费磁盘。

逐张转换记录、尺寸、编码质量、源 SHA-256、输出 SHA-256 和 PSNR 见
`dist/compact-webp-v2/compression-report.json`；完整性与 HTTP 检查见其 `verification.json`。
验证器会核对所有资源内容散列、所有改变的截图尺寸和画质、所有案例与步骤数据，
并检查各 App 入口及每条案例的首尾截图和预览的 HTTP 返回。

## 发布边界

这个副本仍沿用 compact 资源服务，**不是可以直接上传 GitHub Pages 的普通目录**。
减小包的体积与完成 Pages 静态分包是两项不同工作；当前尚未发布或推送任何资源。
后续已新增并校验 [Pages 纯静态分包](PURE_STATIC_PAGES.md)，可使用该布局避免在线 Python 服务。
Pages 主站与独立静态资源项目的组织方式可以参考
[OpenMobile2 的部署调查](OPENMOBILE2_DEPLOYMENT_AUDIT.md)。

本轮尝试用 Chrome 做视觉验收时，Computer Use 因无法可靠识别当前 URL 而自动停止。
文件、图片和 HTTP 验证不替代实际浏览器视觉与全部 App 功能验收。
