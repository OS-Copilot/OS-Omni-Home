Overview

How far do agents get on work that takes a while?

A computer-using agent is judged today on tasks that end quickly: open a setting, fill a form, find a value. Those tasks are easy to verify, which is why they became the standard, but they do not ask the questions that decide whether an agent is useful — whether it can hold a goal across dozens of steps, recover from a step that went wrong, and carry state from one application to the next.

OS-Omni is built for that setting. Tasks are long-horizon workflows on realistic machines, spread across web, Windows, macOS, Ubuntu and mobile, and every agent is scored under one protocol so results are comparable across platforms rather than only within one.

  1. A cross-platform benchmark of long-horizon workflows. 300 v1 tasks across six platforms and cross-device workflows, with 181 tasks using controlled Open-series applications.
  2. An evaluation of generalist agents under one protocol. Seven models under screenshot-only observation; the best model reaches 68.5% average success.
  3. A leaderboard, per platform and overall. Success rate on each of seven evaluation groups, plus their unweighted average and a human reference.
  4. Reproducible execution and final-state verification. Native adapters, controlled services, durable state checks, and recorded trajectories.

Where workflows break

Visual grounding

Nearby controls and dense document or diagram interfaces lead to incorrect clicks or readings.

State tracking

Information is lost between applications or a required destination is forgotten.

Persistence

The visible interface looks complete, but the saved file or committed record is incorrect.

Platform and timing

Dialogs, delayed loading, and missing confirmations interrupt the workflow.

Section 4.3, p. 9. The paper reports these categories qualitatively; it does not provide numerical error frequencies.

Protocol

Observe. Act.
Verify what remains.

Screenshot-only evaluation with the current screenshot and the three most recent interaction steps and screenshots. Each task is judged from its final environment state.

Reproducible initialization

Restore a platform baseline, materialize task-specific files and application records, and arrange the starting applications.

Native interaction

Desktop runtime adapters, Android ADB, and iOS Appium/XCUITest map a shared action interface to each platform.

Executable final-state evaluation

Check saved documents, databases, application records, and output artifacts after the episode ends. Plausible screenshots alone do not establish success.

Single-platform budget

At most 300 steps and 180 seconds per step, subject to the task specification. Six platforms, 48 tasks each.

Cross-device budget

300–650 steps and 120 seconds per step. A desktop shows its companion Android phone; the agent transfers artifacts and returns results to the phone.

Sources: Sections 2.1–2.4 and 4.1. The Camera Ready does not report training gains, cost curves, quantitative ablations, or confidence intervals; those template charts have been removed.
